# G3 probe: team fork-join cost on the 7120A, 2026-11-05

`scripts/g3-team-probe.sh`, source `src/probe/g3-team.c`. Built with the stack's `knc-cc`
(static musl), `phi-isa-audit`: 0 illegal, 0 suspect. 120 threads, two per core on cores 0-59
(CPU 1+4c and 2+4c), core 60 untouched. 10,000 fork-joins per form, 3 rounds, forms interleaved
inside each round. Token work per thread checked: all sums correct.

TSC: 0.8077 ns per tick in every row (from CLOCK_MONOTONIC over each block) = 1.238 GHz, the
core clock. So cycles below are core cycles.

## Run 1 (first build, no tree forms)
barrier p50 1,752,883 - 1,754,792; counter 27,268 - 27,336; flags 20,376 - 20,378 cycles.

**Discrepancy, not traced:** the flags form is the same code in both builds but its p50 fell
from 20,378 (run 1) to 13,800 (run 2). The binaries differ (the tree forms and `gather` were
added), so code or data placement is the suspect. Until it is explained, only forms measured in
the same binary and the same rounds are compared.

## Consequences
- musl's barrier costs 1.41 ms per fork-join: unusable inside an MD step.
- sander's direct-space `!$omp` region sits inside the per-atom routine, 49,910 regions per step for
  the PrP box. Even at the 8-ary tree's 8.37 us that is 0.42 s per step, against a step budget of
  8.64 ms at 20 ns/day. The loop structure has to change, not only the team.
- A step with about 10 parallel regions costs about 84 us in fork-joins with the 8-ary tree (1 % of
  8.64 ms): affordable.
- Still to measure for the G3 gate: `libomp` built for KNC with its SSE lines removed.
